# Personal Budget API

A layered FastAPI backend for managing personal budgets, transactions, savings goals, and contributions. Built with SQLAlchemy ORM, PostgreSQL, and Alembic migrations.

## Features

- **Auth** — register, login, refresh, and logout with JWT (access + refresh tokens, bcrypt-hashed passwords)
- **Transactions** — create (income/expense), list, get by id, soft-delete
- **Budgets** — create, update, and fetch monthly budget details
- **Dashboard** — aggregated overview of budget and transaction data
- **Savings goals** — full CRUD with computed progress (current amount, remaining, percent, monthly-needed)
- **Savings contributions** — record deposits against a goal; auto-completes the goal when the target is reached; edit and delete supported

## Tech Stack

| Layer      | Technology                                             |
| ---------- | ------------------------------------------------------ |
| Framework  | FastAPI (Python 3.11+)                                 |
| ORM        | SQLAlchemy 2.x `<2.1`                                  |

## Getting Started

### 1. Clone & set up the virtual environment

```bash
git clone <repo-url>
cd budget-app

# Windows (PowerShell)
python -m venv .venv
.venv\Scripts\activate

# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt        # runtime deps
pip install -r requirements-dev.txt    # + dev deps (ruff, pytest)
```

### 3. Configure the environment

Create a `.env` file in the project root. The only **required** variable is `DATABASE_URL`:

```env
DATABASE_URL=postgresql+psycopg2://user:password@localhost:5432/budget_db
```

Optional settings (defaults shown):

| Variable        | Default                                | Description                                 |
| --------------- | -------------------------------------- | ------------------------------------------- |
| `HOST`          | `127.0.0.1`                            | Bind host                                   |
| `PORT`          | `8000`                                 | Bind port                                   |
| `RELOAD`        | `True`                                 | Auto-reload on code change                  |
| `CORS_ORIGINS`  | `["http://localhost:3000"]`            | Allowed CORS origins, e.g. React dev server |
| `JWT_SECRET`    | `dev-only-secret-change-before-deploy` | Signing secret (change in prod)             |
| `JWT_ALGORITHM` | `HS256`                                | JWT signing algorithm                       |

> **Note:** in production, set a strong `JWT_SECRET` and tighten `CORS_ORIGINS`.

### 4. Run the app

```bash
python start.py
```

or directly with uvicorn:

```bash
uvicorn src.main:app --reload
```

The API is served at `http://127.0.0.1:8000`, with all routes under the `/v1` prefix.

- Interactive docs: http://127.0.0.1:8000/docs
- Health check: `GET /` → `{"message": "Budget API is running"}`

### 5. Database migrations

Migrations **run automatically** on app startup (`lifespan` hook runs `alembic upgrade head`), so a fresh start is usually enough.

To manage them manually:

```bash
.venv/Scripts/alembic.exe revision --autogenerate -m "describe the change"   # generate
.venv/Scripts/alembic.exe upgrade head                                       # apply
.venv/Scripts/alembic.exe current                                            # view current revision
```

> **Gotcha:** always review an autogenerated migration before applying it — Alembic sweeps in _unrelated_ model drift alongside your intended change (historically this dropped a unique constraint and altered unrelated columns in this repo).

## API Overview

All endpoints live under the `/v1` prefix. Every route except auth (`register`, `login`, `refresh`) requires an `Authorization: Bearer <access_token>` header.

### Auth (`/v1/auth`)

| Method | Path         | Description                             |
| ------ | ------------ | --------------------------------------- |
| POST   | `/register`  | Create an account, returns token pair   |
| POST   | `/login`     | Log in, returns token pair              |
| POST   | `/refresh`   | Exchange a refresh token for a new pair |
| POST   | `/logout`    | Log out (204)                           |
| GET    | `/user-info` | Current user's info                     |

Access tokens are valid 30 minutes; refresh tokens 30 days.

### Transactions (`/v1/transactions`)

| Method | Path    | Description                     |
| ------ | ------- | ------------------------------- |
| POST   | `/`     | Create a transaction            |
| GET    | `/`     | List transactions               |
| GET    | `/{id}` | Get one transaction             |
| DELETE | `/{id}` | Soft-delete (sets `deleted_at`) |

### Budgets (`/v1/budgets`)

| Method | Path | Description                           |
| ------ | ---- | ------------------------------------- |
| POST   | `/`  | Create a budget for the current month |
| PUT    | `/`  | Update the current month's budget     |
| GET    | `/`  | Budget details for the current month  |

### Dashboard (`/v1/dashboard`)

| Method | Path | Description                   |
| ------ | ---- | ----------------------------- |
| GET    | `/`  | Aggregated dashboard overview |

### Savings (`/v1/savings`)

**Goals**

| Method | Path    | Description                                    |
| ------ | ------- | ---------------------------------------------- |
| POST   | `/`     | Create a savings goal                          |
| GET    | `/`     | List the user's goals (with computed progress) |
| GET    | `/{id}` | Get one goal with computed progress            |
| PUT    | `/{id}` | Edit a goal                                    |
| DELETE | `/{id}` | Soft-delete a goal                             |

**Contributions**

| Method | Path                        | Description                                                         |
| ------ | --------------------------- | ------------------------------------------------------------------- |
| POST   | `/{id}/contributions`       | Record a contribution (201); returns contribution + recomputed goal |
| GET    | `/{id}/contributions`       | List a goal's contributions, newest first                           |
| PUT    | `/{id}/contributions/{cid}` | Edit a contribution (amount/note); returns contribution + goal      |
| DELETE | `/{id}/contributions/{cid}` | Delete a contribution; returns recomputed goal                      |

Design notes:

- A goal's `current_amount` is always the **sum of its contributions** — nothing is stored on the goal row itself.
- `contributed_at` is **forced server-side to today**; the request schema intentionally has no such field.
- When a contribution makes `current_amount >= target_amount`, the goal is auto-flipped to `COMPLETED`; a later edit/delete that drops below target flips it back to `ACTIVE`.
- Negative amounts are allowed (only `0` is rejected) — a negative contribution acts as a withdrawal.

## Architecture

A request flows through five layers, top to bottom:

```
Client (HTTP)
   │
   ▼
Router (src/routers)          route definitions, HTTP status codes,
   │                          Depends() wiring, get_current_user
   ▼
Service (src/services)        business rules, orchestration, exceptions
   │
   ▼
Repository (src/repository)   SQLAlchemy queries, commits
   │
   ▼
Model (src/models)            ORM mapping to Postgres tables
```

Direction of dependencies is strictly downward — routers never touch the DB, services never see HTTP concerns.

**Data passing between layers** uses two explicit shapes instead of leaking ORM objects everywhere:

- `routers/dto/` — plain `@dataclass` DTOs (e.g. `SavingsGoalDto`, `SavingsContributionDto`)
- `schemas/` — Pydantic models for the API boundary (requests in, responses out)
- `mappers/` — stateless converters between schema ⇄ DTO ⇄ entity; the savings mapper also holds pure computed math (`compute_progress`)

**Dependency injection** via FastAPI `Depends`: each router defines a local `get_service`/`get_mapper` so a single mapper (and repo) instance is reused per request.

**Auth** — `src/deps/auth.py` decodes the JWT access token and resolves the user; services and repos receive the `User` object or its id.

## Code Conventions & Gotchas

- **Every PK/FK is a `String` column holding a UUID v7**, generated in Python via `UuidUtil.uuid_v7` — NOT a native Postgres `UUID` type. New FK columns must be `String` too, or the FK fails (`DatatypeMismatch`).
- **Soft deletes** for transactions, budgets, and savings goals: rows keep a `deleted_at` timestamp; list/find queries filter `deleted_at IS NULL`.
- **Deletion vs restore** — `Status` enum strings are the message bodies of status responses ("Deleted Successfully", ...).
- **Ruff**: `python -m ruff format .` and `python -m ruff check .` (run from `src/` for lint; `alembic/` is excluded in `pyproject.toml`).
- Name style in this codebase is `snake_case` for functions but `camelCase` in several pre-existing service signatures (e.g. `svgGoalDto`) — match the file you're editing.
- When importing modules in scratch scripts, import `src.main` first (`mappers` ↔ `services` form a benign circular import if touched independently).
